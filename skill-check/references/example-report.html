Concerns

Ranked worst first. Only things that suggest harm appear here.

1

The telemetry hook executes @azure/mcp@latest from npm on every tracked tool call, so what was audited today is not what runs tomorrow.

hooks/scripts/track-telemetry.sh:316

npx -y @azure/mcp@latest "${mcpArgs[@]}" >/dev/null 2>&1 || true

The version is unpinned and -y suppresses the install prompt. The same pattern is the MCP server itself (.mcp.json:4–5). This is the one finding that survives everything else in the report being clean: the audited artifact is a fetch instruction, not the code that runs.

2

The hook has no matcher, so it fires plugin-wide on every tool call, including sessions with nothing to do with Azure.

hooks/hooks.json:3–13

"PostToolUse": [ { "hooks": [ { "type": "command",
  "command": "bash ${CLAUDE_PLUGIN_ROOT}/hooks/scripts/track-telemetry.sh" } ] } ]

It exits early and quietly when nothing matches, so the cost is a bash process per tool call rather than data. But it runs in every session, and the skill description gives no hint of it.

3

Session IDs are transmitted, and the opt-out is invisible from the skill.

hooks/scripts/track-telemetry.sh:309, :82

[ -n "$sessionId" ] && mcpArgs+=("--session-id" "$sessionId")
...
if [ "${AZURE_MCP_COLLECT_TELEMETRY}" = "false" ]; then

A session ID links events across a whole working session. Microsoft does document both the telemetry and the environment variable at README.md:361–366, so this is disclosed, just not anywhere visible when invoking the skill.

No instruction attack. Nothing in 154 files addresses the reviewer, the model, or "the AI" to override instructions, set a verdict, or suppress reporting. No HTML comments, no zero-width or bidi characters, no base64 blobs, no binaries, and no file whose contents contradict its extension. Every non-Microsoft URL in the tree (gitmcp.io, oauth2.googleapis.com, developer.spotify.com, db-mcp.internal) is an illustrative config sample inside documentation, not a fetch.

The skill runs the other direction on autonomy: trace.md:54 "Never run a query silently", deploy.md:73 "don't silently select", verify-environment.sh:67 "it opens a browser; never run it for them".

To make it acceptable

Named, not applied. None of these changes were made.

  • Set AZURE_MCP_COLLECT_TELEMETRY=false in your environment. This short-circuits track-telemetry.sh:82 before any npx call.
  • To remove the hook rather than mute it, the target is the PostToolUse block at hooks/hooks.json:3–13 and its duplicate at .github/plugins/azure-skills/hooks/hooks.json:3–13.
  • Pinning @azure/mcp@latest to a fixed version would close concern 1 at track-telemetry.sh:316, track-telemetry.ps1:300, and .mcp.json:5.

What could not be checked

  • track-telemetry.ps1 lines 1–179. Unread. It does not fire on macOS, but it ships.
  • The 150 markdown and Python files that were pattern-scanned rather than read line by line. The scans were targeted; a semantic problem in prose would not necessarily surface.
  • The actual contents of @azure/mcp@latest, the package that both the hook and the MCP server download and execute. It is not in this tree and it changes without notice. This is the largest unknown in the review, and no amount of reading these 154 files resolves it.
  • What the telemetry endpoint does with a session ID after receipt. Server-side, not observable from here.

One note on evidence: ~/.npm/_npx/541454632b79112e/package.json references @azure/mcp, confirming the package has been fetched and run on this machine. That alone does not distinguish whether it was the hook, the MCP server, or both.
